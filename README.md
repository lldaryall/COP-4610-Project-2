# COP 4610 Project 2: Linux Kernel Programming

This project explores system call tracing, Linux kernel modules, kernel threads,
linked lists, mutexes, and scheduling. The elevator module models pets moving
between five floors.

## Prerequisites

On the Ubuntu VM, install the compiler, kernel build tools, and tracing utility:

```bash
sudo apt update
sudo apt install build-essential libncurses-dev bison flex libssl-dev \
    libelf-dev dwarves bc strace
```

## Part 1: System Call Tracing

The baseline program `empty.c` is compared with `part1.c`. The Part 1 program
adds five system calls: `write`, `getpid`, `getppid`, `getuid`, and `getgid`.
It avoids `printf` because stdio buffering can add unrelated system calls.

Run the check from the Part 1 directory:

```bash
cd part1
make check
```

The Makefile builds both programs, generates `empty.trace` and `part1.trace`
on the VM, and checks that `part1` makes exactly five more system calls than
the baseline.

## Part 2: Timer Kernel Module

The `my_timer` module calls `ktime_get_real_ts64()` to obtain the current time
in seconds and nanoseconds since the Unix Epoch. Loading the module creates
`/proc/timer`. Each read prints the current time; after the first read, it also
prints elapsed time since the previous read. Unloading the module removes the
proc entry.

Build, load, read, and unload the module on the Linux VM:

```bash
cd part2
make
sudo insmod my_timer.ko
lsmod | grep my_timer
cat /proc/timer
sleep 1
cat /proc/timer
sudo rmmod my_timer
test ! -e /proc/timer && echo "PASS: /proc/timer removed"
```

Ermithe built and tested the module on kernel `7.0.0-31-generic`. I verified that it
loads, appears in `lsmod`, reports current and elapsed time through
`/proc/timer`, and removes the proc entry when unloaded. The compiler-version
warning did not prevent the build from completing. See
[`part2/timer_kernel_verify.md`](part2/timer_kernel_verify.md) for the recorded
verification details.

## Part 3: Pet Elevator

### Add the System Calls and Build the Kernel

Apply the system-call changes to the Linux 6.16.x source tree under `/usr/src`,
then configure, compile, and install the modified kernel:

```bash
cd part3/kernel
sudo ./apply_syscalls.sh /usr/src/linux-<version>
sudo ./build_kernel.sh /usr/src/linux-<version>
sudo reboot
```

After rebooting, confirm that the modified kernel is running:

```bash
uname -r
```

### Build and Run the Elevator

Load the module:

```bash
cd part3
make
sudo insmod elevator.ko
```

Run the syscall smoke test while the elevator is OFFLINE:

```bash
cd tests
make
./syscall_test smoke
```

View the elevator status and unload the module when finished:

```bash
watch -n 1 cat /proc/elevator
sudo rmmod elevator
```

### System Calls

| Number | System call | Return behavior |
| --- | --- | --- |
| 548 | `int start_elevator(void)` | `0` when started; `1` if already active |
| 549 | `int issue_request(int start_floor, int destination_floor, int type)` | `0` for a valid request; `1` for an invalid request; `-ENOMEM` if allocation fails |
| 550 | `int stop_elevator(void)` | `0` when stopping; `1` if already deactivating or OFFLINE |

`syscalls.c` is built into the kernel and forwards each call through an exported
`STUB_*` function pointer. It returns `-ENOSYS` when the elevator module is not
loaded. `src/elevator_syscalls.c` sets the pointers when the module loads and
clears them when it unloads. The handlers call `elevator_activate()`,
`elevator_queue_request()`, or `elevator_deactivate()`.
